## 1. P0 — harus ditutup sebelum produksi

### P0-1. Tagihan SPP bisa dilunasi sendiri lewat form web di produksi — **DITUTUP 23 Nov 2026**

Handler web memanggil `state.PayInvoice` tanpa memeriksa mode demo:

- `internal/httpapi/ui_handlers.go:522` `handleStudentPayInvoice` → `state.PayInvoice` (baris 534)
- `internal/httpapi/ui_handlers.go:985` `handleParentPayInvoiceForm` → `state.PayInvoice` (baris 996)

Bandingkan dengan jalur API yang benar:

- `internal/httpapi/payment_handlers.go:58-61` menolak 404 bila `!s.cfg.DemoMode`.

Tombol memang disembunyikan di template saat demo mati (`student_dashboard.templ:147`,
`parent_portal.templ:246`), tetapi endpoint tetap menerima `POST /student/invoice/pay` dan
`POST /parent/invoice/pay` dengan CSRF milik sendiri.

**Dampak:** siswa/orang tua dapat menandai tagihan `PAID` dan menghasilkan entri `PAYMENT_VA`
plus kwitansi ber-HMAC di ledger — kerugian finansial dan catatan audit palsu.

**Perbaikan:** tambahkan guard `if !s.cfg.DemoMode { 404 }` pada kedua handler (atau pindahkan
guard ke `state.PayInvoice` lewat parameter `allowImmediateSettle`), lalu tambahkan test regresi.

**Status:** guard `404` dipasang di awal `handleStudentPayInvoice` dan `handleParentPayInvoiceForm`;
regresi `TestWebPaymentSettleOnlyInDemoMode` membuktikan produksi 404 dan demo tetap berjalan.

### P0-2. PIN DUDI publik dan approval jurnal tanpa autentikasi — **DITUTUP 23 Nov 2026**

- `internal/ui/pages/public_verify.templ:85` mencetak PIN secara harfiah:
  `"PIN resmi dari nota kerja sama sekolah (demo PT Telkom Akses: 445566 · PT Astra Honda Motor: 112233)"`,
  tanpa syarat `DemoMode`.
- `internal/state/mutations.go:1135` mengembalikan PIN yang benar di pesan error
  (`... demo: %s`), lalu error itu tampil sebagai flash di halaman publik `/verify`.
- `internal/state/mutations.go:1124` memakai default `445566`; `AddPklPlacement`
  (`mutations.go:1044`) memakai default `112233` bila PIN kosong.
- `internal/httpapi/ui_handlers.go:482` `handlePublicDudiApprove` tidak memerlukan sesi; CSRF-nya
  hanya token konstan `csrfTokenFor("verify")` yang bisa diambil dari halaman publik.

**Dampak:** siapa pun dapat menyetujui (`supervisorApproved`) jurnal PKL seluruh siswa, dan PIN
rahasia mitra industri terbuka di internet.

**Perbaikan:** hapus hint PIN dari template; jangan pernah menyertakan PIN di pesan error; simpan
PIN sebagai hash; beri rate limit percobaan; pertimbangkan token per-jurnal (bukan PIN global mitra).

**Status:** hint digit dihapus, PIN baru disimpan `sha256:` (legacy plaintext di-upgrade saat cocok),
error tidak lagi memuat PIN, PIN diredaksi dari payload siswa/TU, dan approval dibatasi 20 percobaan
per 10 menit per alamat. Regresi: `TestApprovePklJournal*`, `TestAddPklPlacement*`,
`TestPklPlacementPinRedacted*`, `TestPublicVerifyPageDoesNotLeakSupervisorPIN`.

## 2. P1 — hardening

### P1-1. Halaman `/verify` membocorkan data ke pengunjung anonim — **DITUTUP 23 Nov 2026**

`internal/httpapi/ui_handlers.go:408` memuat seluruh `officialLetters`, `ledger`, `pklJournals`,
dan `pklPlacements`. Template `public_verify.templ:77-155` lalu merender:

- tabel semua jurnal PKL (nama siswa, aktivitas, kompetensi, perusahaan),
- tombol untuk setiap nomor surat dan nomor kwitansi (enumerasi seluruh ledger),
- surat pertama sebagai hasil default saat `?q` kosong.

Tanpa login, siapa pun bisa memanen daftar siswa magang dan nomor dokumen keuangan sekolah.

**Perbaikan:** render detail hanya setelah kode validasi cocok; jangan kirim daftar global ke
template publik.

**Status:** daftar surat/kwitansi/jurnal tidak lagi dikirim ke template. Halaman hanya me-resolve
kode yang diketik; tab DUDI kini meminta kode jurnal lalu menampilkan satu jurnal + form PIN.
Tidak ada lagi surat pertama sebagai hasil default. Regresi: `TestPublicVerify*`.

### P1-2. OTP reversal Kepala Sekolah bisa dipakai ulang dan tersimpan di ledger — **DITUTUP 23 Nov 2026**

- `internal/state/mutations.go:528` `ExecuteReversal` memverifikasi OTP tetapi tidak menghapus
  `activeHeadmasterOtp` setelah sukses; OTP ber-TTL 5 menit dapat dipakai berkali-kali.
- `mutations.go:573` menulis OTP mentah ke ledger: `"reversalApprovalId": "appr-otp-"+expectedOTP`.
  `staffKeys["treasurer"]` di `internal/state/scope.go` berisi `ledger`, dan `redactKeys` tidak
  menyaring field itu → bendahara dapat membaca OTP yang masih berlaku.
- `internal/httpapi/ui_handlers.go:1599` menaruh OTP di query string flash
  (`redirectWithFlash`), sehingga tersimpan di histori browser dan log reverse proxy.

**Perbaikan:** OTP one-time (hapus setelah dipakai), simpan hash + counter percobaan, jangan
menyimpan OTP di ledger, dan kirim lewat kanal aman (bukan URL).

**Status:** OTP dihapus dari state setelah satu reversal, `otpCode` dibersihkan dari request,
ledger menyimpan referensi acak (`appr-xxxx`), dan flash tidak lagi memuat OTP (kode tampil di
kartu portal kepala sekolah). Regresi: `TestReversalOTPIsSingleUseAndNotPersisted`.

### P1-3. Rate limit login dapat di-bypass lewat `X-Forwarded-For` — **DITUTUP 23 Nov 2026**

`internal/config/config.go:93` menetapkan `TrustProxy = true` secara default di production, dan
`internal/httpapi/server.go:327-332` menerima hop pertama `X-Forwarded-For` tanpa memvalidasi
apakah request benar-benar datang dari proxy tepercaya.

**Dampak:** penyerang mengirim header acak untuk melewati batas 5 percobaan/10 menit per
IP+identifier, dan mencemari IP di access log. Berlaku juga untuk rate limit magic link.

**Perbaikan:** default `false`; aktifkan lewat env hanya bila ada reverse proxy; gunakan
`RemoteAddr` atau daftar proxy yang dikenal, bukan header mentah.

**Status:** `WESMK_TRUST_PROXY` default `false`; saat aktif, hanya hop terakhir yang divalidasi
sebagai IP dan dipakai. Regresi: `TestTrustProxy*`, `TestClientIP*`.

### P1-4. Lost update pada `PUT /api/state` — **DITUTUP 23 Nov 2026**

`internal/httpapi/state_handlers.go:157` (`handlePutState`) melakukan `GetState` → merge →
`PutState` dalam dua statement terpisah tanpa transaksi/row lock. Jalur `admin_tu`/`headmaster`
bahkan menimpa seluruh dokumen.

**Dampak:** dua penulisan bersamaan (mis. orang tua mengirim izin saat guru menyimpan presensi)
saling menghapus; mutasi server yang memakai `UpdateStateAudited` (FOR UPDATE) juga bisa
tertimpa oleh snapshot penuh dari admin.

**Perbaikan:** jalankan merge di dalam `store.UpdateStateAudited` (sudah ada `SELECT ... FOR UPDATE`)
alih-alih `GetState` + `PutState`.

**Status:** merge dan overwrite admin sekarang berjalan di dalam transaksi `FOR UPDATE`; audit
ditulis pada transaksi yang sama. Bootstrap DB kosong tetap dipertahankan lewat fallback
`PutState` untuk demo/import admin.

## 4. Yang sudah benar (jangan diregresikan)

- Password Argon2id; dummy hash menyamakan biaya lookup identifier tak dikenal.
- Sesi Redis, cookie `HttpOnly`/`SameSite=Lax`/`Secure` di production, single-session per akun.
- CSRF nyata: token per sesi (HMAC), `csrfGuard` untuk semua form non-API, cek `Origin` untuk
  seluruh method mutasi.
- RBAC staf: `state.StaffView` allowlist per peran, kunci jawaban hanya untuk guru, OTP tidak
  dikirim ke peran lain.
- Scoping siswa/orang tua memfilter record milik sendiri; nilai & `paidAmount` tidak diterima
  dari klien.
- Ledger append-only + trigger DB, `state_audit_log` ditulis dalam transaksi yang sama dengan
  mutasi (`UpdateStateAudited`).
- Upload dokumen: batas 500 KB, validasi tipe via magic bytes, akses file dicek per pemilik/role.
- Callback pembayaran: HMAC body + timestamp ±5 menit + idempoten.
- `Config.Validate()` fail-closed di production (DATABASE_URL, REDIS_URL, secret, PIN default,
  demo mode).

## 5. Rekomendasi urutan

1. Tutup P0-1 (guard demo pada rute bayar web) dan P0-2 (PIN DUDI publik + endpoint approve).
2. Jadikan OTP reversal one-time dan berhenti menulis OTP ke ledger (P1-2).
3. Minimalkan `/verify` (P1-1) sebelum data nyata masuk.
4. Pindahkan merge `PUT /api/state` ke transaksi `FOR UPDATE` (P1-4).
5. Perbaiki default `TrustProxy` (P1-3), lalu bereskan P2 yang berdampak ke UI pengawas ujian.
